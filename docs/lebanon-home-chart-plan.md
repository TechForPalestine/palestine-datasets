# Plan: add Lebanon to the homepage daily casualty chart (v2)

Branch: `lebanon-home-chart` (off `main`).

## Goal

Fold Lebanon's casualties into the **existing single line** on the new homepage chart (`HomeDailyChartV2`). There is no new series, no stacking and no toggle: the line, the big "killed" number and the injured/casualty totals become Gaza + West Bank + Lebanon. Also add four Lebanon key events as markers.

Leave the old chart (`HomeDailyChart.tsx`, `chart-generator.ts`) alone.

## Background (already in place — do not rebuild)

- The dataset `lebanon_casualties_daily.json` / `.min.json` is in the repo root, generated by `bun run gen-lbdaily` (`scripts/data/v3/lebanon-daily.ts`). Its type is `LebanonDailyReportV3` in `types/lebanon-daily.types.ts`. Read that file's doc comment first.
- Use `killed_cum` / `injured_cum`. These are the **continuous** totals since Oct 8, 2023, already rebased across MoPH's two counting phases. Do **not** use `killed_cum_reported` / `injured_cum_reported`, which reset to zero in phase 2.
- The chart is regenerated on every site build (`scripts/build/pre-build.sh` runs `chart-viz`). No CI or workflow changes are needed.
- `DatasetList`'s `?chartdata=1` filter keeps any doc whose id contains `daily`, so `casualties-daily-lebanon` already appears under "Learn more about this dataset". No change needed.

### Data shape to handle

- There are 197 rows, from **2023-11-14** to **2026-09-25** (Gaza runs daily from 2023-10-07). Rows exist only on report dates, so they are sparse and irregular.
- There is a 456-day gap, **2024-12-04 → 2026-03-05**, covering the ceasefire until MoPH began a new count (phase 2 from 2026-03-02).
- The latest row has 8,433 killed and 29,051 injured, about +11% on the current line.
- Lebanon has **no** children, women, medical, press or civil-defence breakdown.

## Changes

### 1. Generator — `site/src/components/HomeDailyChart/generator/chart-generator-v2.ts`

1. Import `../../../../../lebanon_casualties_daily.min.json`, alongside the existing Gaza and West Bank imports.
2. Build an **as-of lookup**: for each Gaza `report_date`, take the most recent Lebanon row with `report_date <= date`.
   - Before 2023-11-14 the value is `0`. Do not interpolate; the 77 jump on Nov 14 is invisible at this scale.
   - Between reports and through the 456-day gap, carry the last value forward. Do not interpolate.
   - After the last Lebanon row (2026-09-25), carry it forward to the end of the Gaza series.
   - The Lebanon rows are already date-sorted. Walk them with a single pointer inside the existing `reduce` (or assert they're sorted); don't search the whole list per day.
3. Add Lebanon to:
   - `killed` in `slimData`;
   - `injured` in `slimData`;
   - the chart `value` (this is what draws the line and sets the y-scale).
4. **Pitfall — keep the children/women estimates off the Lebanon total.** The current code derives `children` and `women` as `Math.floor(killed * lastXxxReportPct)`, and the percentages are computed against `killed`. If Lebanon is added to `killed` before those lines run, both the percentages and the estimates shift. Fix:
   - Keep a separate `gazaWbKilled` (today's `killed`) and use it for the `lastChildrenKilledReportPct`, `lastWomenKilledReportPct`, `children` and `women` calculations.
   - Add Lebanon only to the `killed` that goes into `slimData`, and to the chart `value`.
   - `medical`, `press`, `civdef`, `starved`, `seekingAid` and `settlerActs` stay as they are (Gaza/West Bank only).
5. Optional: add `lebanonKilled` / `lebanonInjured` to `SlimData` if the component wants them for copy. They aren't required for this plan; skip them unless used.
